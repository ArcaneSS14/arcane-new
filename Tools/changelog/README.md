# Журнал изменений Arcane

`Resources/Changelog/ArcaneChangelog.yml` — основной журнал Arcane. Вкладки апстрима сохраняются отдельно. Начальная история восстановлена по 22 PR нового репозитория с заполненным видимым CL (46 пунктов). Ещё 15 проверенных PR без видимого CL или с незаполненным шаблоном не включены. История старого репозитория не импортируется.

## Записи из PR

В описании PR:

```text
:cl: Автор, Соавтор
- add: Добавлена новая возможность.
- fix: Исправлена ошибка.
- tweak: Изменено существующее поведение.
- remove: Удалена устаревшая возможность.
```

Автор необязателен: по умолчанию используется аккаунт создателя PR. Поддерживаются кириллица, `🆑`, строки без маркера списка и продолжения с отступом. Примеры в комментариях и блоках кода игнорируются. Следующий Markdown-заголовок завершает CL. Шаблонные записи про «веселье», пустые блоки и неизвестные категории считаются ошибкой. PR без видимого CL, включая закомментированный блок, пропускается без записи в игре и Discord. Пропуски и ошибки перечисляются в логах и GitHub Actions Job Summary со ссылками на PR; ошибки CL дополнительно создают предупреждения. Название PR не подставляется вместо CL.

По умолчанию записи идут в `ARCANE`. Существующие категории `TRAUMA`, `WIZDEN`, `WIZDENADMIN`, `MAPS`, `ADMIN`, `RULES` сохранены. Ссылки из раздела `## Медиа` / `## Media` сохраняются рядом с записью.

## Сбор и восстановление

После merge самого сборщика и после каждого последующего merge в основную ветку выполняется полная сверка закрытых PR этой ветки с GitHub, включая пропущенные события. Она также запускается каждый час и вручную через PR Changelogs. Начальный список из 22 записей не ограничивает сбор: порты Orion, Goob, Arcane и другие PR с CL, слитые до установки сборщика, будут обнаружены автоматически. Push-триггер следит за кодом сборщика и его workflow, поэтому коммит с готовым журналом не запускает сам себя.

Используется REST-пагинация по 100 PR в порядке создания; редактирование описания не перемещает PR между страницами. Отдельный запрос каждого PR при сверке не нужен. Принадлежность недостающих merge-коммитов проверяется относительно ревизии checkout. Каждый затронутый журнал читается и записывается один раз за пакет. Повторная сверка без новых записей не изменяет файлы и не создаёт коммит.

Записи располагаются по времени merge, а не номеру PR или порядку получения события. Восстановленный старый PR вставляется на своё место; уже назначенные ID не меняются. Discord также сохраняет порядок merge внутри новой партии; ранее отправленные сообщения не переставляются.

Уникальность определяется ссылкой на PR, поэтому повтор события или запуск сверки не создаёт дубликат. Существующие записи не переписываются по изменённому описанию PR. Проверенная начальная история помечена `historical`; её правят непосредственно в журнале. Исторические дубликаты в унаследованных журналах не блокируют сбор: старые строки сохраняются, новые дубликаты не добавляются.

В PR допускается один видимый блок `:cl:` или `🆑`. Несколько блоков дают ошибку в отчёте; частичная запись такого PR не публикуется. Примеры в fenced/indented code и незакрытых HTML-комментариях не считаются CL. Медиа из inline-кода также не публикуется.

Прочитанные записи Arcane сохраняются по ссылкам PR отдельно для каждого сервера. Поэтому временные ID сборки не сбивают состояние после записи журнала в Git. При переходе на этот формат старые числовые отметки намеренно не переносятся. Восстановленные старые PR показываются в секции непрочитанного над существующим разделителем; даты упорядочены внутри секций. Компоновка и элементы вкладки сохранены.

Перед упаковкой Publish повторяет сверку, проверяя принадлежность недостающих merge-коммитов собираемой ревизии через GitHub Compare. В игру и Discord попадает один и тот же журнал. Его фактически опубликованная версия сохраняется в артефакте `published-changelog`; сравнивать только YAML из Git-коммита недостаточно, поскольку запись могла быть восстановлена непосредственно при сборке.

Запросы чтения PR имеют таймаут и ограниченные повторы при временных ошибках. Ошибка загрузки страницы прерывает сбор до записи файлов. Ошибки генерации и push не скрываются; следующая сверка восстанавливает пропуски.

## Discord

Нужен секрет репозитория `CHANGELOG_DISCORD_WEBHOOK`. Сообщения отправляются только после успешной публикации версии. Отсутствующий webhook считается ошибкой доставки.

Карточки используют Discord Components V2: автор, дата, ссылка на PR, русские категории, цветовой акцент и галереи. Исторические записи явно обозначены. Длинный CL делится на несколько сообщений без сокращения текста: до 3000 UTF-16 единиц основного текста в части, с запасом под заголовок и подпись, до 10 медиа в галерее. Разбиение проходит по тексту линейно; все сообщения заранее в памяти не собираются.

Медиа загружает Discord по публичным URL. Runner не скачивает произвольные ссылки из PR. Если Discord отклоняет галерею, текст и ссылки отправляются отдельно. Доступность и предпросмотр внешнего медиа зависят от источника и Discord. Упоминания пользователей и ролей отключены.

Подтверждённые сообщения и неопределённые попытки записываются в `delivery.json`, сохраняемый как `changelog-delivery-<attempt>`. До отправки сохраняется полный набор карточек данного PR: исправление описания PR между неудачными публикациями не меняет уже начатую рассылку. Повтор восстанавливает последнее подготовленное состояние по времени артефакта и пропускает доставленные части. После отклонения галереи сохраняется выбранный набор текстовых сообщений; повтор продолжает именно его. HTTP 429 повторяется ограниченно; потерянный ответ на POST и HTTP 5xx автоматически не повторяются, поскольку сообщение могло быть принято.

Если повтор старой сборки или удаление записей откатывает журнал относительно последней успешной рассылки, доставка завершается ошибкой до отправки. Такая попытка не становится новой базой сравнения и не провоцирует повторную рассылку удалённых записей при следующей сборке.

При неопределённой доставке скачайте последний артефакт подтверждений: в `messages` указаны заголовки частей и ID подтверждённых сообщений. После проверки канала запустите Publish вручную:

- `changelog_confirmed`: хеши сообщений из `pending`, которые уже присутствуют в канале;
- `changelog_retry`: хеши сообщений, отсутствие которых проверено;
- `changelog_base_run`: аварийный выбор завершённой публикации той же ветки, **весь** CL которой уже подтверждён. Нельзя выбирать частично доставленную публикацию.

Артефакты хранятся 90 дней. При утрате подтверждений после попытки отправки или истечении срока снимка автоматическая доставка останавливается для проверки. Это предотвращает слепую повторную рассылку, но требует ручного восстановления после неоднозначного сбоя.

## Проверка без публикации

Workflow `Changelog tests` запускает проверки сборщика и доставки при изменениях соответствующего кода и workflow. Тесты используют поддельные HTTP-ответы и не обращаются к Discord.

Из корня репозитория, с установленными `js-yaml`, `requests` и `PyYAML`:

```text
node --test Tools/changelog/changelog.test.js
python -m unittest discover -s Tools/changelog -p test_discord.py
```

`SS14_CHANGELOG_DEBUG=1` переводит отправщик в режим формирования JSON без сети. Предыдущий журнал читается из `Resources/Changelog/Old.yml`, путь результата задаётся `CHANGELOG_DEBUG_OUTPUT`. Обычный debug-предпросмотр использует тот же рендерер, что отправка.

Поведение карточек и медиа адаптировано из [старого Arcane](https://github.com/ArcaneSS14/arcane/blob/57c2612f1bee06f88e5d08da4b3057a364663a83/Tools/actions_changelogs_since_last_run.py), включая семейство PR #362 и последующее исправление повторов ссылок. Сборщик сохраняет формат категорий текущего апстрима; пакетная сверка и подтверждения доставки добавлены для нового Arcane.
